## วิธีเก็บข้อมูล 2 ชั้น

**เพิ่มคอลัมน์ `categories.group_name`** (VARCHAR, nullable) — เก็บ "กลุ่มหลัก" ของแต่ละหมวดย่อยที่มีอยู่แล้วในตาราง `categories`

```sql
ALTER TABLE categories ADD COLUMN group_name VARCHAR(100) NULL AFTER name;
```

**ทำไมไม่ใช้วิธีอื่น:**
- ❌ ไม่ยัด `"กลุ่มหลัก › หมวดย่อย"` เป็น string เดียวใน `kpi_reports.category` — จะพัง exact-match ที่ใช้อยู่จริง (KpiWizard dropdown, `/api/categories` DELETE guard, export Excel, filter ใน admin)
- ❌ ไม่ทำ self-referencing `parent_id` — overkill สำหรับ 2 ชั้นตายตัว
- ✅ `group_name` เป็นคอลัมน์ใหม่คอลัมน์เดียว ไม่กระทบ `kpi_reports` เลย ไม่กระทบ dropdown ใน KpiWizard (ยังเลือกหมวดย่อยเหมือนเดิม)

**หมายเหตุจากภาพจริง:** HDC เอง "dual-list" บาง KPI ไว้ 2 เมนู (เช่น คัดกรอง DM/HT + มะเร็ง โผล่ทั้งใน "ส่งเสริมป้องกัน>การคัดกรอง" และใน "Service Plan" สาขาที่เกี่ยวข้อง, TEDA4I โผล่ทั้ง "ส่งเสริมป้องกัน>อนามัยแม่และเด็ก" และ "การเข้าถึงบริการ>สุขภาพจิต") — ระบบเราเก็บ 1 หมวดต่อ 1 KPI จึงเลือก**บ้านหลักที่มีรายละเอียดครบกว่า/ตรงเนื้อหามากกว่า**เป็นตัวยืนตามตาราง mapping ด้านล่าง
