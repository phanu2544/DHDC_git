## 5. กฎที่พลาดแล้วเจ็บ (เจอมาแล้วจริง)

- **ห้าม commit เอง** จนกว่า owner สั่ง
- **DB = `dhdc_dev` เท่านั้น** (127.0.0.1:3306 root/123456) · ห้ามแตะ production
- **SQL ที่มีภาษาไทย → ใช้ไฟล์ `.sql` เท่านั้น** ห้าม `mysql -e "..."` inline (ค่าเพี้ยน)
- **JSON ที่มีภาษาไทย → `curl --data-binary @file`** ห้ามใส่ใน argument ตรงๆ
- **`npm run build` ขณะ dev server เปิดอยู่ = dev server พัง** (`Cannot find module './xxxx.js'`) → หยุด dev ก่อน build เสมอ แล้ว `rm -rf .next` ก่อนสตาร์ทใหม่
- **`PUT /api/kpis/[id]` ไม่ใช่ partial update** — ต้องส่ง field ครบ ไม่งั้นทับเป็น NULL · `deadline` ต้องแปลง ISO → `YYYY-MM-DD` ก่อน
- **DB op ทุกครั้ง:** backup → preview/gate → COMMIT → **verify ผ่าน browser จริง**
- console ของ Windows แสดงไทยเพี้ยน — **verify ต้องอ่านจาก DB/browser ไม่ใช่ stdout**
- **ก่อนลบข้อมูล (`DELETE /api/monthly` ฯลฯ) ต้อง confirm กับ user ก่อนเสมอ** แม้จะมี audit log/backup ก็ตาม (ระบบ auto mode บล็อกไว้ให้แล้วระดับหนึ่ง แต่ต้องถามชัดเจน)

| **carry-forward ทำคำเตือนหายเงียบ** | เปลี่ยนความหมายของ `value === null` แล้วต้องไล่หาทุกที่ที่พึ่งพามัน |
| **🆕 เส้น auto ไม่เขียน `data_change_log` เลย** — กรอกมือตอน API ล่ม แล้ว auto ทับทีหลัง = ค่าหายเงียบไม่มีร่องรอย | **เส้นเขียนข้อมูลทุกเส้นต้อง audit เท่ากัน** — เส้น manual ทำครบมาตลอด แต่เส้น auto ถูกมองข้ามเพราะ "auto ทับ auto ไม่เป็นไร" ลืมไปว่าข้อมูลใต้เส้นเดียวกันอาจมาจากคนละมือ · แก้แล้ว `logAutoOverwriteIfManual` |
| **🆕 whitelist คอลัมน์ผูกกับ `moph_table` แต่ข้อมูล manual เป็น `{target,result}`** — สลับเป็นกรอกมือแล้วตาราง drilldown ไม่มีคอลัมน์เลย (10 ตาราง) | **ทดสอบตัวอย่างเดียวไม่พอถ้าตัวอย่างนั้น "บังเอิญถูก"** — ทดสอบ `s_dm_control` แล้วผ่านเพราะ field ชื่อ target/result ตรงกันพอดี ต้องไล่ดูว่าตัวอื่นชื่อเหมือนกันไหมก่อนสรุปว่าไม่พัง |
| **🆕 (11 ส.ค.) mysql2 คืน DECIMAL column เป็น string เสมอ ("100000.00") — `<select value>` ไม่ match กับ `<option value={100000}>`** dropdown เด้งกลับตัวเลือกแรกเงียบๆ ทั้งที่ DB ถูก | **ค่าจาก DECIMAL column ที่จะเอาไปใช้กับ `<select>` ต้อง `Number()` ก่อนเสมอ** — `<input type=number>` ทนกับ string ได้เลยไม่เคยเจอบั๊กนี้มาก่อน (เช่น `target`) แต่ `<select>` ต้อง string ตรงเป๊ะ ระวังเวลาเพิ่ม field ใหม่ที่ผูกกับ select |
| **🆕 single-mode เดาค่า B/A คืนจาก % แทนที่จะเก็บของจริง** (ตั้งแต่ Phase I เดิม 19 ก.ค. — เพิ่งเจอ 6 ส.ค. ตอนทดสอบกรอกจริง) เปิดฟอร์มแก้ไขซ้ำ → ค่าเพี้ยนสะสมทุกครั้ง (บาง KPI เพี้ยนน้อยจนสังเกตไม่ออก เช่น 83→82.67) | **field ที่ชื่อคล้ายกัน (`kpi.target` = เกณฑ์ผ่าน/ไม่ผ่าน vs "กลุ่มเป้าหมาย B" ที่ผู้ใช้กรอก) ต้องไม่ปนกัน แม้ตัวแปรจะดูเข้าคู่กันในหน้าจอ** · ถ้าจะ "คำนวณย้อน" ค่าที่ไม่ได้เก็บไว้ ให้สงสัยไว้ก่อนว่าจะพังเงียบ — เก็บของจริงดีกว่าเดาเสมอ · แก้แล้ว: `kpi-keyin-plan.md` Phase 1 |
| **🆕 #26 target ผิดหน่วย ทำ "ไม่ผ่าน" หลอกทุกไตรมาส** (3 ส.ค.) — ตั้ง `kpi_reports.target` เป็นบาท (7,416,619) แต่ระบบ manual scope='single' เอา **% ที่คำนวณจาก B/A รายเดือน** ไปเทียบกับ target เสมอ ไม่ใช่เทียบ B/A ดิบ | **KPI แบบ "กรอกค่าเอง" มี 2 ชั้นหน่วยห้ามสับสน:** (1) target/result **รายเดือน** = ตัวเลขดิบหน่วยอะไรก็ได้ ใช้แค่คำนวณ % (2) `kpi_reports.target` **ของ KPI เอง** = ต้องเป็น**%เสมอ** เพราะเทียบกับ %ที่คำนวณได้ · แก้โดยตั้ง `direction=none` ไว้ก่อนจนกว่าจะรู้เกณฑ์ %จริง — **ควรไล่เช็ค manual-single KPI อื่นที่เคยแก้ target ว่าใส่ถูกหน่วยไหม (ยังไม่ได้ทำ)** |
| **🆕 hospcode/areacode ที่ตาราง MOPH ติดมาไม่ใช่ของจริงเสมอไป** — `s_child0_5_pshyche_develop_coverage` ให้ hospcode `00948` ซึ่งเช็คกับ `hcode.moph.go.th` แล้วเป็นหน่วยงานคนละจังหวัด (สมุทรปราการ) + รหัสซ้ำกันข้ามอำเภอ | **ต้อง cross-check field ที่ดู "เหมือนใช้ระบุพื้นที่/หน่วยงาน" กับแหล่งทางการเสมอ** ก่อนใช้เป็น label — บาง table ใส่ field พวกนี้มาแบบไม่มีความหมาย (คอลัมน์มาตรฐานที่ทุกตารางมีติดมา) |
| **🆕 บาง MOPH table ปฏิเสธ param `province`** (`s_ttm4`... ไม่ใช่ `s_child0_5_pshyche_develop_coverage` — เจอ 400 "Parameter Invalid" ถ้าใส่) | เพิ่ม `NO_PROVINCE_TABLES` ใน `lib/mophEngine.ts` ให้จุดที่เรียก MOPH API เช็คก่อนใส่ province — ต้องดึงทั้งประเทศแล้วกรอง areacode เอง (ตอนนั้นมี 3 จุด — 13 ส.ค. รวมเหลือจุดเดียวแล้ว ดูแถวถัดไป) |
| **🆕 (13 ส.ค.) MOPH API เปลี่ยน response เป็น envelope `{data,total,limit,offset}` หลังล่มแล้วกลับมา (เดิมคืน array ตรงๆ) + มี `limit` เริ่มต้น 1000 แถว/คำขอ** — unwrap เดิม (`Array.isArray(raw)?raw:Object.values(raw)`) เจอ object แปลกก็ไม่ throw แค่ได้ array ผิดรูป → กรอง areacode เหลือ 0 แถวเงียบๆ + ตารางใหญ่โดนตัดข้อมูลทิ้งเงียบเหมือนกัน (ซ้ำกัน **4 จุด**ในโค้ด ไม่ใช่ 3 อย่างที่คอมเมนต์เก่าเขียนไว้ — เจอจุดที่ 4 ตอนแก้จริง) | **API ภายนอกเปลี่ยน contract ได้โดยไม่แจ้ง แม้ endpoint ที่ใช้มานานแล้ว** — unwrap แบบ "ทนทาง" (`else Object.values(raw)`) อันตรายกว่าที่คิด เพราะรับ shape ผิดแล้วไม่ error เงียบไปเป็นค่าที่ "ดูสมเหตุสมผล" (array สั้นๆ) แทนที่จะ fail ชัดเจน แก้โดยเพิ่ม guard เทียบจำนวนแถวที่ได้กับ `total` ที่ API บอกเองแล้ว throw ถ้าไม่ครบ — ไม่ใช่แค่ unwrap ให้ถูก ต้อง**ยืนยันว่าครบ**ด้วยเสมอ · รวมจุดที่เรียก MOPH เป็นตัวกลางเดียว (`lib/mophFetch.ts`) กันลืมจุดใดจุดหนึ่งซ้ำแบบนี้อีก |
