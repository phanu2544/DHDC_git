## 5. กฎที่พลาดแล้วเจ็บ (เจอมาแล้วจริง)

- **ห้าม commit เอง** จนกว่า owner สั่ง
- **DB = `dhdc_dev` เท่านั้น** (127.0.0.1:3306 root/123456) · ห้ามแตะ production

- **JSON ที่มีภาษาไทย → `curl --data-binary @file`** ห้ามใส่ใน argument ตรงๆ

- **DB op ทุกครั้ง:** backup → preview/gate → COMMIT → **verify ผ่าน browser จริง**
- console ของ Windows แสดงไทยเพี้ยน — **verify ต้องอ่านจาก DB/browser ไม่ใช่ stdout**
- **ก่อนลบข้อมูล (`DELETE /api/monthly` ฯลฯ) ต้อง confirm กับ user ก่อนเสมอ** แม้จะมี audit log/backup ก็ตาม (ระบบ auto mode บล็อกไว้ให้แล้วระดับหนึ่ง แต่ต้องถามชัดเจน)

MOPH API เปลี่ยน response เป็น envelope `{data,total,limit,offset}` หลังล่มแล้วกลับมา (เดิมคืน array ตรงๆ) + มี `limit` เริ่มต้น 1000 แถว/คำขอ** — unwrap เดิม (`Array.isArray(raw)?raw:Object.values(raw)`) เจอ object แปลกก็ไม่ throw แค่ได้ array ผิดรูป → กรอง areacode เหลือ 0 แถวเงียบๆ + ตารางใหญ่โดนตัดข้อมูลทิ้งเงียบเหมือนกัน (ซ้ำกัน **4 จุด**ในโค้ด ไม่ใช่ 3 อย่างที่คอมเมนต์เก่าเขียนไว้ — เจอจุดที่ 4 ตอนแก้จริง) | **API ภายนอกเปลี่ยน contract ได้โดยไม่แจ้ง แม้ endpoint ที่ใช้มานานแล้ว** — unwrap แบบ "ทนทาง" (`else Object.values(raw)`) อันตรายกว่าที่คิด เพราะรับ shape ผิดแล้วไม่ error เงียบไปเป็นค่าที่ "ดูสมเหตุสมผล" (array สั้นๆ) แทนที่จะ fail ชัดเจน แก้โดยเพิ่ม guard เทียบจำนวนแถวที่ได้กับ `total` ที่ API บอกเองแล้ว throw ถ้าไม่ครบ — ไม่ใช่แค่ unwrap ให้ถูก ต้อง**ยืนยันว่าครบ**ด้วยเสมอ · รวมจุดที่เรียก MOPH เป็นตัวกลางเดียว (`lib/mophFetch.ts`) กันลืมจุดใดจุดหนึ่งซ้ำแบบนี้อีก |
