## ⛔ อ่านก่อน — ข้อจำกัดที่พิสูจน์แล้ว

1. **MOPH Open Data API ไม่มี endpoint "list ตารางทั้งหมด"** — มีแต่ `POST https://opendata.moph.go.th/api/report_data` ที่ต้อง**ระบุ `tableName` เอง** → **ค้นหาอัตโนมัติไม่ได้ ต้องรู้ชื่อตารางก่อน**
2. KPI เดิม 38 ตัวที่ดึงได้ **ไม่ได้เก็บ URL หน้า HDC ไว้** (`moph_url` ว่างทั้งหมด) → ไม่มี mapping "หน้า HDC → ชื่อ table" ให้ลอกแล้ว
3. **ห้ามเดาชื่อ table** (CLAUDE.md ข้อ 5) — ต้อง Preview เห็นข้อมูลดงเจริญจริง + เทียบเลขกับ HDC ก่อนใช้เสมอ

## ✅ ข้อ 6 — sepsis community-acquired → `s_kpi_sepsis_septic` (เสร็จ 3 ส.ค. 2569)

**ที่มา:** owner ส่งชื่อตาราง + ลิงก์นิยาม `https://fileex.moph.go.th/media/00366a85bd3c2b6932a228df29137252-2564.png`
(ชื่อไฟล์ `00366a85...` = `id` ของแถวดงเจริญในตารางนั้นพอดี → ยืนยันว่าเป็นตารางเดียวกัน)

### นิยามจากเอกสาร (ตรวจราชการปีงบ 64 ตัวชี้วัด 38)
```
A = ผู้ป่วย sepsis community-acquired ที่เสียชีวิต (ICD10 R65.1/R57.2 · ไม่นับ Post Admission Comorbidity · ไม่นับ palliative Z51.5)
C = ผู้ป่วยที่ปฏิเสธการรักษากลับไปเสียชีวิตที่บ้าน (Discharge status=2, type=3)
D = ผู้ป่วย sepsis community-acquired ทั้งหมด
สูตร = (A + C) / D × 100      ระยะประเมิน = รายไตรมาส      เป้า ปีงบ 64 < ร้อยละ 26
```

### โครงตาราง (พิสูจน์จาก API จริง)
`id · hospcode · areacode · date_com · b_year · targetq1-4 · resultq1-4 · result2q1-4 · result3q1-4`

🔑 **เลขเป็นรายไตรมาสแยกกัน ไม่ใช่ยอดสะสม** — พิสูจน์จาก รพ.พิจิตร (10726) `tq1=134 → tq2=113 → tq3=83` **ลดลง** ถ้าเป็นยอดสะสมต้องเพิ่มขึ้นเท่านั้น

ดงเจริญ (hospcode 27980 · areacode 66110502): Q1 `0/0` · Q2 `1/3` · Q3 `1/10` · Q4 `0/0`

### mapping ที่ใช้ (owner เคาะ 3 ส.ค.)
```json
{"fieldMode":"sumFields","aggregate":"sum","calcMode":"percent",
 "valueFields":["resultq1","resultq2","resultq3","resultq4"],
 "targetMode":"field","targetFields":["targetq1","targetq2","targetq3","targetq4"]}
```
= **ทั้งปีงบสะสม 4 ไตรมาส** → ตาย 2 / ผู้ป่วย 13 = **15.38%** (เป้า <26 → ผ่าน)

ทางเลือกที่เสนอแล้ว owner ไม่เลือก: เฉพาะไตรมาสของรอบส่ง (รอบ 1 = ไตรมาส 2 = **33.33% → ไม่ผ่าน**) · เหตุผลที่เลือกสะสม: ทั้งระบบตีความตัวเลขเป็น **ยอดสะสมปีงบ** (carry-forward L4b พึ่งข้อนี้) และแบบเดียวกับ FIT test (`s_colon_screen_w`) ที่ sum ทุกไตรมาสอยู่แล้ว

### 🟡 ยังไม่รู้ — ต้องถามเจ้าภาพก่อนเชื่อไตรมาสถัดไป
**`result2q*` / `result3q*` คือค่าอะไร ยังไม่ยืนยัน** — เดาว่าอาจเป็น B (against advice) กับ C (กลับไปเสียชีวิตที่บ้าน) แยกช่อง ถ้าใช่ สูตรจริงต้องเป็น `(result + result3) / target`
- **ตอนนี้ไม่กระทบดงเจริญ** เพราะ `result2`/`result3` = **0 ทั้ง 4 ไตรมาส** → คิดแบบไหนก็ได้ 15.38% เท่ากัน
- **แต่กระทบ รพ. อื่น** เช่น 11259 Q1: `result/target` = 1/5 = 20% แต่ `(result+result3)/target` = 2/5 = 40%
- → **ถ้าไตรมาสหน้าดงเจริญมี result3 ไม่เป็น 0 ต้องกลับมาเคาะสูตรก่อน** · ยังไม่ใส่ `lib/detailLabels.ts` ด้วยเหตุผลเดียวกัน (drilldown จึงโชว์ field ดิบครบ 16 ช่อง = เห็นทุกอย่าง ไม่ซ่อน)

### เพิ่ม 3 ส.ค. (ต่อเนื่อง 2) — owner ส่งนิยาม B/C เต็มจากเอกสารทางการ
owner ยืนยันนิยาม B/C ที่เคยทำเครื่องหมาย "ยังไม่ยืนยัน" ไว้:
- **B** = ปฏิเสธการรักษา กลับบ้านอาการดีขึ้น (Discharge type=2 ปฏิเสธการรักษา, status=2 ดีขึ้น)

**บริบท:** API ล่มทั้งระบบตั้งแต่ 3 ส.ค. (nginx 404 ทุก endpoint — ดู log ข้อ 26 ด้านบน) เช็คซ้ำวันนี้ (13 ส.ค.) → **กลับมาแล้ว** ยิงครบ **41/41 ตาราง** ที่ระบบใช้จริง ตอบ 201 พร้อมข้อมูลสดถึง 12 ส.ค. 69 (`date_com=202608121209`) ทุกตัว

### 🔴 แต่ API เปลี่ยนรูปแบบระหว่างที่ล่ม — โค้ดเดิมพังเงียบ (0 แถวทุกครั้ง ไม่ throw)
1. **response ห่อ envelope แล้ว** — เดิมคืน array ตรงๆ ตอนนี้คืน `{data:[...rows], total, limit, offset}` (`total` เป็น **string** เช่น `"5953"`) โค้ด unwrap เดิม `Array.isArray(raw) ? raw : Object.values(raw)` เจอ object ที่ไม่ใช่ array → ได้ `[Array(121),"121",1000,0]` (4 element ปนกัน) → กรอง areacode 6611 เหลือ **0 แถวเงียบๆ ไม่มี error**
2. **มี `limit` เริ่มต้น 1000 แถว/คำขอ** — ตารางที่ `total` เกิน 1000 ถูกตัดข้อมูลทิ้งอัตโนมัติ (ทดสอบแล้วว่า `limit`/`offset` ใช้งานได้จริงสำหรับ paginate)

### แก้โค้ด — รวมจุดที่เรียก MOPH API ให้เหลือที่เดียว
เดิมคิดว่ามี 3 จุด (ตามคอมเมนต์เก่าใน `NO_PROVINCE_TABLES`) — **ตอนแก้จริงเจอจุดที่ 4** คือ `app/api/detail/route.ts` (import `fetchMOPH` จาก `lib/mophBatch.ts` เพื่อดึง live สำหรับ drilldown) เนื้อโค้ด unwrap เหมือนกันเป๊ะ บั๊กเดียวกัน

สร้าง **`lib/mophFetch.ts`** เป็นตัวกลางตัวเดียว (`fetchMophRows(tableName, year, province)`) แล้วให้ 4 จุดเรียกใช้แทนของเดิม — ลบฟังก์ชัน `fetchMOPH`/`MOPH_API` ที่ก๊อปกันไว้ทั้งหมด:
- `lib/mophBatch.ts` (batch/cron) · `app/api/moph/route.ts` (ปุ่มดึงทีละตัว + preview) · `lib/monthlyView.ts` (drilldown live fallback) · `app/api/detail/route.ts` (drilldown live)

ตัวกลางทำ: (1) unwrap ทนทาง — รับได้ทั้ง array แบบเก่าและ envelope แบบใหม่ (2) paginate ผ่าน `offset` จนครบ `Number(total)` หน่วง 300ms/หน้า (3) **throw ถ้าดึงได้ไม่ครบ total** (กันพังเงียบซ้ำ) (4) retry 3 ครั้งเมื่อเจอ 429 (5) เพดาน 50 หน้า กันลูปไม่รู้จบถ้า `total` ผิดปกติ (6) timeout 30s→60s ต่อคำขอ (เจอคำขอแรกแบบ cold ใช้ 27.8 วิ เฉียด 30s เดิม) · คง `NO_PROVINCE_TABLES` เดิมไว้ (ยังปฏิเสธ province เหมือนเดิม)
