# ข้อมูลตัวอย่างจริง — ตัวชี้วัดทั้ง 80 ตัว

> ไฟล์ประกอบ `design-brief.md` · ดึงจากระบบจริง (อำเภอดงเจริญ ปีงบ 2569)
> **ใช้ชุดนี้ทำ mockup ห้ามแต่งข้อมูลใหม่** — สัดส่วนสถานะ ความยาวชื่อ และความบางของข้อมูลย้อนหลัง คือโจทย์จริงที่ layout ต้องรองรับ

## ⚠️ อ่านก่อน — 3 เรื่องที่ทำให้ดีไซน์สวยแต่ใช้ไม่ได้

**1. ตัวที่ "ประเมินผ่าน/ไม่ผ่าน" ได้จริงมีแค่ 37 จาก 80** — ที่เหลือเป็นติดตามเฉยๆ เชิงคุณภาพ หรือยังไม่มีข้อมูล

**2. ข้อมูลย้อนหลังบางมาก** — ระบบเพิ่งเริ่มเก็บ ยังไม่มีตัวไหนครบ 12 เดือน

| มีข้อมูลกี่เดือน | จำนวนตัวชี้วัด |
|---|---|
| 4 เดือน | 3 |
| 3 เดือน | 1 |
| 2 เดือน | 39 |
| 1 เดือน | 15 |
| ยังไม่มีเลย | 22 |

> **กราฟแนวโน้มจะว่างเปล่าสำหรับตัวชี้วัดส่วนใหญ่** — ถ้าจะใส่กราฟเส้น/sparkline ต้องออกแบบสถานะ "ข้อมูลไม่พอวาดกราฟ" ให้ดูดีด้วย ไม่ใช่โชว์กราฟแบนๆ

**3. แต่ละตัวเก็บคนละเดือนกัน** — ไม่ใช่ทุกตัวมีข้อมูลเดือนเดียวกัน

|---|---|
| ธ.ค. 2568 | 3 |
| มี.ค. 2569 | 20 |
| มิ.ย. 2569 | 41 |
| ก.ค. 2569 | 36 |

> หน้าจอต้องสื่อให้ชัดว่าตัวเลขแต่ละตัวเป็น "ณ เมื่อไร" ไม่ใช่สมมติว่าทุกตัวเป็นเดือนเดียวกัน
